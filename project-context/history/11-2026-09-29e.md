> - **Pictures under load.** `views/flowcharts._node_available` asks PATH (`shutil.which`) before

> - **Jobs left running.** At start-up the API fails every queued, running or paused job with
>   `INTERRUPTED_MESSAGE` and frees its draft version (`pipeline_runner.fail_interrupted_jobs`, via
>   the new `jobs.list_active()`). It does so only while it holds the two-key session advisory lock
>   `_RUNNER_LOCK` (`claim_job_runner`, held for the process's life). A second server on the same
>   database sweeps nothing: failing its live jobs would delete the drafts it is still generating,
>   which is why `web-app/PLAN.md` had ruled a sweep out. SQLite serves one process: it sweeps. Checked
>   on PostgreSQL with three processes: holder True, second False, third (after the first exits) True.
> - **RF-6.** `analyzer.py setup` runs `review/backfill.py` on every version. For a version generated
>   with `llm.descriptions` on (its `resolved_config`) that stores no description of a kind, it copies
>   the version's own earlier output into the model: unit text from `unit_descriptions.json` (not
>   `N/A`), record text from `unit_headers.json`, matched to the data-dictionary record by the name its
>   declaration declares (`class X`, `struct X`, a typedef alias). A name-derived sentence, or two rows
>   that disagree, copies nothing. A re-export then keeps the wording, and a correction's LLM original
>   and its undo are that wording. Reading the old output at export time instead would have broken
>   undo: after a correction and a re-export, the old output holds the correction. On `analyzer_ui`:
>   3 unit and 17 struct descriptions in 2 versions; a second run stores nothing.
